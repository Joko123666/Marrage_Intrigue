## 현재 기준선

- Godot 프로젝트명은 `Marriage intrigue`이며 메인 씬은 `res://scenes/main/Main.tscn`이다.
- `project.godot`의 현재 기능 태그는 Godot `4.7`, 렌더러는 GL Compatibility, 기준 뷰포트는 1280×720이다.
- Autoload는 `DataManager`, `GameState`, `TimeManager`, `ActionResolver`, `SaveManager` 5개다.
- 현재 파일 기준으로 GDScript 39개, JSON 데이터 19개, `Smoke*.gd` 스크립트 12개가 있다.
- 핵심 루프는 자유행동 → 후보 발견/정보 수집 → 맞선 → 결혼 → 배우자 관리 → 제거 또는 정치적 처리 → 은폐/후폭풍 → 다음 작위 후보 접근으로 구성된다.
- 현재 주요 UI 조정자는 `scripts/ui/Main.gd`이며 2,634줄이다. 대시보드, 자유행동, 상점, 인물, 맞선 화면은 `scripts/ui/screens/`로 분리되어 있다.
- `export_presets.cfg`의 `Windows Desktop` 프리셋으로 `build/windows/MarriageIntrigue.exe`를 생성할 수 있다.
- `assets/art/` 기준 PNG 52개·약 73.1MB이며 NPC 23명의 기본 초상 경로는 모두 유효하다. 주인공·상시 생활 배경은 각 1개, 배우자 4상태 초상 세트는 18후보 중 2명, 맞선 3상태 초상 세트는 기사 핵심 후보 3명이 보유하고 자유행동 결과 장면 배경은 3개다.
- 자유행동은 카테고리별 장면 표지, 현재 수행감, 최종 예상 효과를 카드에 표시하고 완료 시 행동별 생활 서술·실제 변화·경과 주차를 전용 결과 장면으로 출력한다. 맞선은 직전 턴의 축별 증감, 화법 상태, 후보 반응, 교섭 분위기를 같은 장면에서 강조한다.
- 이 작업공간 경로에서는 Git 저장소가 감지되지 않았다. 변경 이력을 Git으로 복구할 수 있다고 가정하지 않는다.

## 최근 결정

- 2026-09-01: `TimeManager.advance_weeks()`는 월 변경 여부와 무관하게 매번 `time_passage` 피드백을 발생시킨다. 범용 장면은 특정 행동 배경 대신 밤→새벽 궤적, 시작/도착 주차, 최대 6개 주차 눈금을 사용하고 같은 달·월 전환·연도 전환의 문구와 강조만 단계화한다. 행동 결과는 기존 피드백 큐에서 시간 경과 뒤에 이어진다.
- 2026-09-01: 맞선은 《총성과 다이아몬드》의 표면 미학 대신 교섭 유불리에 따른 공간 장력만 참고한다. 순효과가 양수면 중앙 장력선과 초상이 후보 쪽·중앙으로 가까워지고, 음수나 `backfire`면 플레이어 쪽·바깥으로 밀린다. 주요 축 색, 반복 권태 감쇠, 배경 광원·휘장·촛불 반응을 같은 `match_turn` 이벤트에서 파생하며 실제 패널 폭과 텍스트 배치는 고정한다.
- 2026-09-01: 맞선 화제는 첫 사용만 정상 효과를 내고, 2회째부터 긍정 효과 감쇠와 흥미 하락, 3회째부터 안심 하락, 4회째 이후 신뢰 하락을 더한다. 버튼에 다음 반복 단계와 실제 예상 효과를 함께 표시하고 `choice_history`/`choice_usage`를 저장 상태에 포함한다. 기사 밸런스 기준은 동일 화제 8회 실패와 4종 이상 화제 조합 성공이다.
- 2026-08-30: 맞선 선택 후에는 선택 직전 스크롤 위치를 복원하고 카드에 `[1]~[9]` 단축키를 표시한다. 터치 화면은 관련 능력 평균과 권장치를 카드 본문에 표시한다. 시간·행동 결과는 아래 입력을 차단하고 클릭/Enter로 넘길 수 있으며, 모바일 일반 화면 행동 로그는 기본 접힘으로 둔다. 새 게임과 기존 저장 덮어쓰기는 공통 확인 패널을 거친다.
- 2026-08-30: 맞선 후보 표정은 직전 선택 전·변화량 0이면 `neutral`, 축 합계가 양수면 `favorable`, `backfire` 또는 축 합계가 음수면 `wary`를 사용한다. 전용 `match_portraits`가 없는 후보는 기본 `portrait`와 기존 상태 색조로 폴백한다.
- 2026-08-30: 육성 결과 배경은 행동 10개마다 개별 생성하지 않고 `거울방(외모·가면·휴식)`, `서재(교양·예법·사교)`, `시장 골목(상점·잡일·소문)` 3개 장면군을 공유한다. `result_backdrop` 데이터로 선택하며 중앙 암막과 독립된 느린 배경 정착 애니메이션을 사용한다.
- 2026-08-30: 기본 루프 연출 1차는 새 대형 일러스트보다 정보의 인과 연결을 먼저 보정한다. 육성 결과는 `action_result` 장면으로 서술·최종 효과·주차를 묶고, 맞선 결과는 축 `▲/▼`·양측 상태·초상 색조·대사 패널 강조를 같은 반응 상태에서 파생한다. 월 전환과 연속 행동 결과는 큐로 순차 재생한다.
- 2026-08-30: 맞선 소프트 요구가 정확히 40%일 때 원래 긍정 효과를 0으로 만들어 `역효과(-)→중립(0)→감소 효과(+)`로 전환한다. 맞선 중 `stats/*`가 바뀌면 카드 화면을 지연 일괄 갱신하고, 8개 선택지 경계와 대표 선택지 왕복 전환은 기존 스모크 테스트에 영구 포함한다.
- 2026-07-30: 맞선의 `충분` 상태는 기존 대사 단계별 템플릿을 유지하고, `효과↓`와 `역효과`는 선택지의 `state_dialogue` 전용 문장을 우선 출력한다. 전용 문장이 없으면 공통 머뭇거림/실언 문장을 사용하며 상대 반응과 이전 화제의 숙련 결과도 같은 상태로 기록한다.
- 2026-07-30: 맞선 선택지의 숫자형 플레이어 능력치 요구는 선택을 막지 않는 소프트 요구로 취급한다. 현재치가 권장치의 100% 이상이면 정상, 40~99%면 이득 감소·불이익 증가, 40% 미만이면 이득이 역효과로 바뀐다. `hard_requirements`, 비능력치 조건, 자원 비용만 하드 잠금으로 남긴다.
- 2026-07-29: 대시보드는 생활 공간 속 주인공, 월간 목표, 최대 3개 장기 행동 일정, 능력/평판/위험 장부, 하단 행동 리본을 첫 화면에 둔다. 일정은 확정 전 계획이므로 저장하지 않으며 실행 중 조건을 잃으면 남은 행동을 중단한다.
- 2026-07-29: 맞선의 실제 6축 판정은 유지하되 화면은 호감·신뢰·체면·정략 가치의 핵심 리본과 흥미·안심 보조 지표로 표현한다. 전투 용어와 청·적 결투 배경 대신 응접실 대화 교섭 문법을 사용한다.
- 2026-07-29: UI 리디자인은 고전 육성 시뮬레이션의 `생활 공간 속 주인공`, `상시 날짜/자원 장부`, `주간 일정`, `능력 수첩` 문법을 참고하되 원작 자산은 복제하지 않는다. `Marriage intrigue`는 양피지·궁정 남색·포도주색과 위험/정보/정략 수치로 차별화한다.
- 2026-07-29: 맞선 화면은 청·적 전투 HUD보다 응접실의 인물 표정, 대사, 관계 리본, 선택지 예상 변화를 중심으로 재구성한다.
- 2026-07-29: 컨텍스트 간 공유 정보는 이 파일 하나를 원장으로 사용한다. 상세 명세와 장기 체크리스트는 기존 `docs/` 문서를 계속 사용하고 여기에는 요약과 인수인계 정보만 둔다.
- 2026-07-29: 실제 코드·데이터·실행 결과가 이 문서보다 우선한다. 불일치를 발견한 컨텍스트가 이 문서를 즉시 바로잡는다.

## 알려진 문제와 위험

- 맞선은 선택 후 기존 스크롤을 복원하지만 첫 턴에는 전장·대사 아래 선택지까지 한 번 내려가야 한다. 이후 완전한 하단 고정 선택지 구조가 필요하면 전용 화면 레이아웃을 더 분리해야 한다.
- 시간 경과·행동 결과는 입력 차단과 클릭/Enter 넘기기를 지원하고 맞선 연출은 `accessibility/reduce_motion` 프로젝트 설정을 읽지만, 사용자가 직접 바꾸는 모션 축소·연출 속도 옵션 화면은 아직 없다.
- 모바일 일반 화면의 행동 로그는 기본 접힘으로 개선했지만 헤더·달력·자원 HUD와 다줄 내비게이션 자체는 여전히 세로 공간을 많이 차지한다.
- 게임의 핵심 성장 서사는 6개 대사 단계와 10개 페르소나를 갖지만 주인공 초상과 상시 생활 배경은 각각 1개뿐이다. 자유행동 완료 장면은 3종으로 보강됐으나 평민 고아에서 궁정 권력자로 상승하는 상시 변화는 아직 거의 보이지 않는다.
- 후보 18명 중 배우자 `neutral/affectionate/suspicious/weakened` 4상태 초상 세트는 아드리엔과 루카스 2명만 있다. 나머지 16명은 상태 수치가 변해도 기본 초상으로 폴백한다.
- 결혼식 3종, 제거/정치처리 5종, 은폐 행동 5종, 수직 절편 완료와 게임오버는 전용 장면 이미지 없이 같은 저택 복도 위 텍스트 패널로 표시된다. 상승혼 루프의 전환점과 위험의 감정적 무게가 약하다.
- 오디오·효과음·내장 한글 폰트·게임 전용 앱 아이콘이 없다. 맞선 긴장, 결혼, 의심 상승, 제거와 은폐의 피드백이 시각 토스트와 로그에만 의존하고 배포물은 기본 Godot 아이콘을 사용한다.
- 후보 기본 초상은 18명 모두 있으나 512×640부터 1024×1536 이상까지 원본 해상도와 크롭·노출이 혼재한다. 런타임 PNG의 단순 RGBA8 환산은 약 120.9MB이고 import에 크기 제한·mipmap이 없어 작은 카드 표시 대비 원본이 큰 편이다.
- 자유행동 결과 배경 3종은 각 1672×941이고 원본 합계 약 6.13MB, 단순 RGBA8 환산 약 18.9MB다. 현재 결과 패널에서는 584×308 안팎으로 표시하므로 이후 전체 초상 정규화 작업과 함께 import 크기 제한을 검토한다.
- 기사 핵심 후보 3명은 맞선 `neutral/favorable/wary` 표정 초상을 보유하지만 남작 이상 후보 15명은 기본 초상과 색조·테두리만 사용한다. 중앙 교섭판의 분위기 해석은 추가됐으나 비주얼 목업의 인물 중심 응접실 교섭에는 아직 미치지 못한다.
- 40% 경계의 긍정 효과는 0으로 완충됐지만 기존 부정 효과는 계속 증폭된다. 따라서 일부 선택지는 경계에서 완전한 무변화가 아니라 부작용만 남으며, 후보별 체감 밸런스 관찰이 필요하다.
- 새 맞선 선택지를 추가할 때 `state_dialogue`를 생략해도 공통 대사로 동작하지만, 인물성과 화제 맥락을 살리려면 `reduced`·`backfire` 문장을 함께 작성해야 한다.
- 맞선 소프트 요구의 역효과 기준 40%와 효과 배율은 `data/match/match_config.json`에서 조정 가능하지만, 상위 작위 후보를 포함한 장기 플레이 밸런스 검증이 더 필요하다.
- `scripts/ui/Main.gd`에 후보, 배우자, 처리, 은폐 화면 조정 로직이 남아 있어 변경 영향 범위가 넓다.
- UI 캡처 도구는 headless dummy renderer에서 동작하지 않으며 Windows display driver가 필요하다.
- 생성 목업은 시각 목표이며 최종 UI 텍스트·아이콘 자산으로 직접 쓰지 않는다. 작은 한글과 수치는 실제 Godot `Label`/`TextureRect` 구성으로 재현해야 한다.
- 대시보드 구조는 구현됐지만 성장 단계별 방 배경과 주인공 의상은 아직 단일 이미지로 표시된다.
- 일정은 현재 상태 기준 총 주차·누적 효과를 보여주고 중단 시 남은 계획을 보존하지만, 앞 행동의 결과를 순차 반영한 정밀 예측과 드래그 순서 교체 UI는 아직 없다.
- 현재 작업공간에 Git 이력이 없어 동시 컨텍스트가 같은 파일을 수정할 때 충돌과 복구에 특히 주의해야 한다.
