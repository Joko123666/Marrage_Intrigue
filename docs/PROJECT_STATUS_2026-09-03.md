## 1. 한눈에 보는 결론

현재 프로젝트는 **기사 튜토리얼부터 결혼, 배우자 관리, 처리와 은폐, 다음 작위 후보 접근까지 플레이 가능한 확장형 MVP**다. 핵심 상태 전이, 저장/불러오기, 데이터 로딩, 자유행동, 맞선, 결혼 이후 위험 관리가 실제 코드로 연결되어 있으며 Windows 실행 파일도 존재한다.

로컬 안정성은 양호하다. 2026-09-03에 프로젝트 headless 로딩, 기존 Windows 릴리스 기동, JSON 19개 파싱, 스모크 테스트 12개를 다시 실행했고 모두 통과했다. 데이터에 기록된 `res://` 리소스 참조 38개도 실제 파일과 모두 일치했다.

다만 **출시 준비 완료 상태는 아니다.** 최종 목표인 왕족 후보와 엔딩이 없고, 상위 작위 후보의 고유 맞선 콘텐츠와 장기 밸런스가 부족하다. 오디오·내장 한글 폰트·전용 앱 아이콘이 없으며, 배포 메타데이터와 CI도 완성되지 않았다. `Main.gd`에 남은 화면 로직이 많고 현재 작업 폴더에는 Git 저장소도 없다.

## 3. 현재 플레이 가능한 게임 구조

```text
14세 평민 고아 시작
→ 주간 일정과 자유행동으로 능력·자금·정보 확보
→ 소문·인물 상호작용으로 후보 발견 및 정보 품질 상승
→ 후보 최소 조건과 결혼 준비금 확인
→ 8턴 혼인 교섭
→ 결혼식 선택
→ 배우자 관계·가문 압박 관리
→ 치명적 제거 또는 비치명 정치 처리
→ 사건 파일과 은폐·후폭풍 관리
→ 다음 작위 후보 접근
→ 기사→남작→자작→백작→후작→공작 확장
```

시간은 1주 단위로 진행된다. 52주마다 나이가 증가하고, 30세부터 혼인 시장 페널티가 적용되며 35세는 종료 조건으로 사용된다. 결혼은 최종 보상이 아니라 다음 신분으로 이동하기 위한 중간 거점으로 설계되어 있다.

현재 데이터는 공작 단계까지 제공하지만 **왕족 후보, 왕족 맞선, 최종 승리 조건과 복수 엔딩은 미구현**이다. 따라서 현재 완성 범위는 전체 기획의 최종판이 아니라 반복 가능한 상승혼 수직 절편에 가깝다.

## 6. UI와 연출 상태

현재 UI는 고전 육성 시뮬레이션의 정보 구조를 참고해 다음 요소를 사용한다.

- 생활 공간 속 주인공, 월간 목표, 3칸 일정, 능력 장부를 묶은 대시보드
- 양피지·궁정 남색·포도주색 기반 카드와 자원 HUD
- 데스크톱 3열, 컴팩트 2열, 모바일 1열 반응형 구성
- 행동별 생활 장면, 실제 수치 변화와 경과 주차를 묶은 결과 연출
- 모든 주간 행동에 공통으로 적용되는 밤→새벽 시간 경과 연출
- 맞선에서 양측 초상, 대사, 핵심 관계 리본, 6축 보조 지표를 함께 표현
- 순효과·주요 축·반복 단계에 반응하는 응접실 광원과 중앙 장력선
- 맞선 화제 반복 경고, 숙련 부족 상태와 실제 예상 효과 표시
- 일반 화면 전환 스크롤 초기화, 모바일 로그 기본 접힘

UI 캡처 파일은 `tmp/`에 61개가 남아 있고, 현재 `CaptureUi.gd`는 48개 상태를 생성하도록 정의되어 있다. 최근 기준 캡처에는 1280×720, 820×720, 640×760과 행동 결과·맞선 상태·결혼·배우자·처리·은폐·게임오버가 포함된다.

남은 핵심 연출 공백은 성장 단계별 방·의상 변화, 결혼식과 처리/은폐의 대표 전환 장면, 상위 후보 표정 변화, 음향 피드백이다.

## 9. 주요 위험과 기술 부채

1. **버전 관리 부재**  
   프로젝트 루트와 상위 작업 폴더 모두 Git 저장소가 아니다. 대규모 리팩터링이나 병렬 작업 전에 복구 가능한 기준점이 필요하다.

2. **`Main.gd` 집중**  
   2,634줄·162개 함수에 화면 라우팅, 공통 UI와 후보·배우자·처리·은폐 로직이 함께 있다. 변경 영향 범위가 넓고 화면 단위 테스트가 어렵다.

3. **최종 목적 미완성**  
   공작 이후 왕족 접근과 최종 엔딩이 없어 장기 성장의 결론이 없다.

4. **상위 후보의 전술적 유사성**  
   18명 중 전용 맞선 화제는 4명뿐이다. 상위 계급은 수치 요구가 높아지지만 후보별 금기·반격·해법의 차이가 충분하지 않다.

5. **비주얼 상태 커버리지 부족**  
   배우자 상태 초상은 2명, 맞선 표정 세트는 3명뿐이다. 성장 단계별 주인공 방·의상과 주요 전환 장면도 없다.

6. **오디오·폰트·앱 아이덴티티 부재**  
   소리와 자체 폰트가 없고 기본 아이콘을 사용해 완성품 인상이 약하다.

7. **자동화 공백**  
   현재 12개 테스트는 유효하지만 로컬 실행에 의존한다. JSON 파싱, 프로젝트 로딩, 스모크 테스트와 빌드 기동을 한 번에 검증하는 CI가 필요하다.

8. **성능·용량 최적화 필요**  
   작은 UI 카드에 비해 일부 원본 초상이 크고 크롭·해상도가 통일되지 않았다. import 크기 제한과 텍스처 기준을 정할 필요가 있다.

## 10. 권장 다음 작업 순서

1. 현재 동작 상태를 보존할 Git 저장소와 `.gitignore` 기준을 마련한다.
2. 상위 작위 후보에게 정보 품질 기반 고유 화제, 금기, 반격 패턴을 추가한다.
3. 공작 이후 왕족 후보·접근 조건·최종 승리와 엔딩 분기를 설계하고 구현한다.
4. 후보·배우자·처리·은폐 화면을 `scripts/ui/screens/`로 분리한다.
5. 기사부터 공작까지 자동 장기 진행 시뮬레이션으로 경제·나이·반복 감쇠를 검증한다.
6. 성장 단계별 방/의상과 결혼식·처리·은폐 전환 연출을 우선순위대로 보강한다.
7. 모션 축소·연출 속도 설정과 모바일 헤더/내비게이션 압축을 구현한다.
8. 오디오·한글 폰트·전용 앱 아이콘과 Windows 배포 메타데이터를 확정한다.
9. JSON 파싱→프로젝트 로딩→12개 스모크→Windows 빌드 기동을 CI로 자동화한다.
