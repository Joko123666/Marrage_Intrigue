# 단계별 구현 백로그 v0.1

## Phase 0. Godot 프로젝트 부트스트랩

목표: 실행 가능한 빈 프로젝트를 만든다.

작업:

1. Godot 4.x 프로젝트 생성.
2. `res://data/`와 `res://scripts/autoload/` 구조 생성.
3. `DataManager.gd`, `GameState.gd`, `TimeManager.gd`, `ActionResolver.gd`를 Autoload로 등록.
4. `Main.tscn`에서 새 게임 시작 버튼을 만든다.
5. `DataManager.load_all()`이 모든 JSON을 읽는지 확인한다.

완료 기준:

- 게임 실행 시 JSON 로드 성공.
- 새 게임 시작 시 14세/1주차/초기 스탯이 세팅됨.

## Phase 1. 1주 단위 시간/자유행동

목표: 자유단계에서 행동을 누르면 시간이 흐르고 스탯이 변한다.

작업:

1. `FreeActionScreen.tscn` 생성.
2. `free_actions.json`에서 행동 목록을 읽어 버튼 생성.
3. 행동 요구조건/비용/효과 적용.
4. 주차, 나이, 피로, 자금 UI 갱신.
5. 행동 로그 표시.

완료 기준:

- 외모 관리 실행 시 2주가 지나고 외모/가면/피로/자금이 변함.
- 휴식 실행 시 피로가 감소함.

## Phase 2. 주인공 대사 단계/페르소나

목표: 현재 대사 단계와 페르소나가 UI와 선택지 보정에 반영된다.

작업:

1. `dialogue_stages.json`, `personas.json`, `choice_tags.json` 로드.
2. 현재 대사 단계/페르소나 표시 UI 생성.
3. 페르소나 변경 UI 생성.
4. 페르소나 요구조건과 유지 비용 적용.
5. 대사 템플릿 선택 함수 작성.

완료 기준:

- 같은 상황 대사가 대사 단계에 따라 다르게 출력됨.
- `골목의 생존자` 페르소나는 하급/뒷세계 행동에 보정, 고위 사교 행동에 페널티를 줌.

## Phase 3. 캐릭터/관계 시스템

목표: 상인, 정보상, 후보, 라이벌을 데이터로 표시하고 관계 축을 변경할 수 있다.

작업:

1. `npcs.json` 로드.
2. 캐릭터 목록 UI 생성.
3. 관계 축 표시.
4. 대화/선물/거래/소문전 같은 기본 상호작용 버튼 생성.
5. 관계 변화 로그 작성.

완료 기준:

- 재단사와 거래하면 아이템 접근.
- 정보상과 거래하면 후보 정보 품질이 증가.
- 라이벌은 출신 소문 위험을 올릴 수 있음.

## Phase 4. 상점/아이템

목표: 아이템 구매와 장착/보정이 작동한다.

작업:

1. `items.json` 로드.
2. 상점 UI 생성.
3. 구매 조건, 가격, 인벤토리 처리.
4. 장착 슬롯 처리.
5. 아이템 효과가 스탯/행동/맞선에 반영되게 한다.

완료 기준:

- 고쳐 입은 드레스 구매/장착 시 외모가 오르고 출신 소문이 낮아짐.

## Phase 5. 소문 조사/유포

목표: 정보력과 소문 위험을 게임 루프에 연결한다.

작업:

1. `rumor_actions.json` 로드.
2. 소문 주제 목록 UI 생성.
3. 탐문/씨앗 뿌리기/소문 희석 실행.
4. 성공/실패 판정 및 위험 변화.

완료 기준:

- 소문 조사로 기사 후보 정보가 열림.
- 소문 유포 실패 시 사회적 의심이 상승함.

## Phase 6. 후보 색출/정보 품질

목표: 후보가 정보 품질에 따라 다르게 표시된다.

작업:

1. `candidate_profiles.json` 로드.
2. 후보 목록 UI 생성.
3. 정보 품질 단계별 표시 필드 제한.
4. 맞선 요청 조건 판정.
5. 거절 시 준비 기간 손실 이벤트 구현.

완료 기준:

- 정보 품질 0에서는 공개 요약만 보임.
- 정보 품질 60 이상에서는 보안/특성이 보임.

## Phase 7. 맞선 레이더 시스템

목표: 제한 턴 동안 선택지를 골라 레이더 축을 올리고 성공/실패를 판정한다.

작업:

1. `MatchScreen.tscn` 생성.
2. 6축 레이더 차트 또는 막대 UI 임시 구현.
3. 맞선 선택지 5개 데이터 적용.
4. 페르소나/스탯/아이템 보정 반영.
5. 제한 턴 종료 후 성공 점수 계산.

완료 기준:

- 아드리엔 기사와 맞선 성공/실패가 가능함.
- 야성 선택지는 흥미를 올리지만 안심/체면을 낮춤.

## Phase 8. 결혼/배우자 대시보드

목표: 결혼 후 배우자 상태와 주변 인물을 보여준다.

작업:

1. `WeddingScreen.tscn` 생성.
2. 결혼식 옵션 선택.
3. 배우자 상태 생성.
4. `SpouseDashboardScreen.tscn` 생성.
5. 건강/애정/직접의심/경계도/공개금슬 표시.

완료 기준:

- 결혼 성공 시 married 플래그와 배우자 데이터가 생김.

## Phase 9. 제거/정치처리 MVP

목표: 배우자를 처리하는 방식 2~3개를 비교 선택할 수 있다.

작업:

1. `removal_methods.json` 로드.
2. 제거 준비 UI 생성.
3. 요구조건, 성공률, 위험 프로필 표시.
4. 실행 결과로 사건 파일 생성.
5. 실패 시 직접의심/경계도 상승.

완료 기준:

- 사고사 위장, 추문 실각 중 최소 2개가 작동함.
- 실패 시 경계도와 의심이 상승함.

## Phase 10. 은폐 사건 파일

목표: 제거 후 은폐 행동을 늦게 하면 위험이 커진다.

작업:

1. `coverup_actions.json` 로드.
2. 사건 파일 UI 생성.
3. 조사 진행도/소문 확산도/증거 위험도/알리바이/공개 애도 표시.
4. 매주 위험 자동 증가.
5. 은폐 행동 성공 시 위험 감소.
6. 범인 지목/게임오버 조건 임시 구현.

완료 기준:

- 제거 후 1주마다 조사와 소문이 진행됨.
- 공개 애도/알리바이/공식 소견으로 위험을 낮출 수 있음.

## Phase 11. 기사 튜토리얼 수직 절편 완성

목표: 첫 30~60분 플레이 루프를 완성한다.

완료 흐름:

```text
시작 → 자유행동 → 기사 후보 발견 → 맞선 → 결혼 → 배우자 대시보드 → 처리/은폐 → 남작 후보 열림
```

완료 기준:

- 처음부터 끝까지 리셋 없이 플레이 가능.
- 플레이어가 최소 1번 성공, 1번 실패, 1번 위험 상승을 경험함.
